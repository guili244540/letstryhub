# Evolution: standalone editor download from the built dist site

> **Status: IN PROGRESS.** This plan adds the "Download standalone
> editor" capability to the Vite-built site (`npm run build` →
> `dist/`), which today does not offer it. The `page/` folder keeps
> working exactly as before.

## 1. Goal

After `npm run build`, the deployed `dist/` site contains, next to the
Vite app bundle:

- a copy of `page/bpmnEditor.html` (the fully standalone editor), and
- an added **"Download standalone editor"** button in the built
  `index.html` that downloads that copy in one click.

The button must also work when the dist site is served under a sub-path
(the existing Pages workflow deploys branches under `/dev/` and `/exp/`),
and degrade gracefully in `npm run dev` (where the file is not copied).

## 2. Current state (inventory)

- `page/bpmnEditor.html` (2.6 MB, generated by `npm run inline-lib`) is
  the fully standalone editor: bpmn-js, styles, extras and sample
  diagram are all inlined; it works offline via `file://` with no
  other files needed.
- `page/bpmnEditorOnLine.html` and `page/bpmnSample.html` have the
  button plus a handler: on `http(s)` they `fetch('bpmnEditor.html')`
  (same directory), blob-download it; on `file://` they just point at
  the file. The generated `page/bpmnEditor.html` hides the button
  (downloading a copy of itself would be redundant).
- The Vite app (`index.html` + `src/modeler.js`) has no such button.
  `npm run build` produces only the JS/CSS bundle for `index.html` and
  `viewer.html` in `dist/`; nothing from `page/` is copied, so the
  deployed dist site cannot offer the download.
- The GitHub Pages workflow does not build or deploy `dist/` at all —
  it ships the `page/` files directly (root from `main`, `dev/` from
  `development`, `exp/` from `experimental`). Those surfaces already
  have the button and are **not** touched by this plan; the new button
  matters for any dist-based deployment (and anyone who runs
  `npm run build` + `npm run preview` or serves `dist/` themselves).
- `src/modeler.js` owns the header-button handlers (open, save,
  export, toggle panel) and reports outcomes in the `#status` span.
- Vite `base` is unset (absolute asset paths, root deployment); this
  plan does not change that, it makes the button path-agnostic
  instead.

## 3. Design rules going forward

1. **Each slice is shippable on its own** and must leave
   `npm run check:pages` green.
2. `page/bpmnEditor.html` stays generated output: it enters `dist/`
   only by copying, never by hand-editing or re-templating.
3. The button handler is **new code in the Vite app** (`src/`), kept
   close to the other header handlers in `src/modeler.js`; the
   parallel surfaces in `page/` already have their own working copy
   and are not modified (parameterize per-surface differences, do
   not unify them silently).
4. `dist/` remains disposable — regenerated by `npm run build`, never
   edited, never committed.

## 4. Steps (slices, in order)

### Slice 1 — Copy `page/bpmnEditor.html` into `dist/` at build time

In `vite.config.js`, add a `closeBundle` plugin hook (internal
plugin, in-file) that copies `page/bpmnEditor.html` into the bundle
output directory (use the hook's resolved `build.outDir`, not a
hardcoded `dist`). This hook fires once per build config; the extra
config (`vite.config.extras.js`) is a separate process and is
untouched.

*Checks:* `npm run build` completes; `dist/bpmnEditor.html` exists and
is byte-identical to `page/bpmnEditor.html`; `npm run build:extras`
still writes only `page/lib/`; `npm run check:pages` green.

### Slice 2 — Add the button and handler to the Vite editor app

- Add `<button id="download-standalone">Download standalone
  editor</button>` in `index.html` after the Export button, before the
  Properties toggle (mirroring the header layout of the standalone
  pages).
- In `src/modeler.js`, add a handler aligned with the existing code
  style (status feedback via `#status`, `async` click handler):
  - resolve the editor file relative to the current document with
    `new URL('bpmnEditor.html', document.baseURI)` so the button works
    both at a site root and under a sub-path (`/dev/`, `/exp/`);
  - on `http(s)`: `fetch` it, throw on non-ok, blob-download as
    `bpmnEditor.html`, status "Downloaded bpmnEditor.html — fully
    standalone, works offline via file://.";
  - on `file://`: no fetch (browsers block it); status message
    explaining the file lives in `page/` in a repo checkout;
  - on any error: status "Download failed: … — the file is
    bpmnEditor.html, next to this page."
- In `npm run dev` the copy step never ran, so the fetch fails and
  the error path explains where the file is — acceptable and stated
  in the README note.

*Checks:* `npm run build` then `npx vite preview` (loopback): the
button appears, the click downloads `bpmnEditor.html`, status shows
the success message; `npm run dev`: button click shows the graceful
failure status. `npm run check:pages` green.

### Slice 3 — Update the docs surface

- `README.md`: state that the built site (`dist/`) includes
  `bpmnEditor.html` next to the bundle and that the editor app header
  offers the one-click download (works when `dist/` is served over
  http(s); `npm run dev` does not ship the file).
- AGENTS.md surface matrix: no editor-behavior change in `src/`
  beyond the new self-contained handler; note the dist copy step next
  to the existing build guidance so future slices keep it in mind.

*Checks:* docs match the observed behavior (re-read after the
slices); `npm run check:pages` green.

## 5. Constraints and non-goals

- No change to `page/bpmnEditor.html`'s button behavior (it hides its
  own button) or to any `page/` file: they already ship the feature.
- No change to the Pages workflow or deployment layout: `dist/` is not
  what Pages serves today, and this plan does not alter that.
- No new dependencies; the copy uses a ~10-line Vite plugin hook.
- No `base`/publicPath changes; the handler resolves the file against
  `document.baseURI` instead.
- `page/lib/` stays pinned to one bpmn-js version; `dist/` remains
  disposable, never committed.

## 6. Verification protocol (after each slice)

1. `npm run check:pages` — exits non-zero on drift.
2. `npm run inline-lib`, `npm run build`, `npm run build:extras`
   complete cleanly.
3. `cmp page/bpmnEditor.html dist/bpmnEditor.html` — byte-identical
   copy check after slices 1–2.
4. Manual smoke test of every affected surface (standalone pages from
   the file system, `npm run dev`, built `dist/` via
   `npm run preview`). In a sandbox without a browser, at minimum run
   checks 1–3 and state which browser checks were not performed.
